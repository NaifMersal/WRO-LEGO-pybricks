B. Finish the Word: D and I

  • P knows how far is left
  • D tracks how fast you close
  • I fights friction and drag

Break it: P in a hurry 🔥

heading = 0°  target 90°

Why P overshoots

  • Checks how far is left, not how fast it is closing
  • Full speed at arrival means momentum carries it past 90°
  • Crank KP higher and it rings even harder

Run it before the fragment. The red arc past the tick is overshoot made visible. Ask students: “the number hit 90 — why didn’t it stop?” Because the wheels were spinning at high speed. P cuts power at error 0, but momentum carries the robot past. Then P pulls back, creating oscillation. We need a way to detect that the error is dropping fast and ease off early.

Name it: D damps 🛑

def gyro_turn_pd(target, kp=4, kd=0.5):
    hub.imu.reset_heading(0)
    last_error = target
    while abs(target - hub.imu.heading()) > 1:
        error = target - hub.imu.heading()    # how FAR (P)
        change = (error - last_error) / 0.005 # how FAST (D, in °/s)
        last_error = error
        left.run(kp * error + kd * change)    # ease off early
        right.run(-(kp * error + kd * change))
        wait(5)
    left.stop(); right.stop()

P (Proportional)

  • Reads where you are
  • Pushes hard when far
  • Engine of the turn

D (Derivative)

  • Reads how fast gap closes
  • Taps the brake before arrival
  • Stops ringing and overshoot 🛑

Focus on the three new lines: remember last error, subtract to get rate of change, and combine into the motor command. When closing fast on the target, error shrinks each loop pass, making change negative. Multiplying by kd subtracts power, giving a smooth deceleration right into 90°.

The last letter: I (Coach Demo) 🧲

Add physical friction or a lean to one side. Why does P stop short and stay there?

🧲 = constant friction/lean
accumulated error (I memory):

P alone stalls: The tiny leftover error makes a push too weak to beat friction.

I (Integral) fixes it: It adds up the leftover error over time, until the motor is strong enough to beat the drag.

Coach demo only; not a required implementation for students. When a small error remains, KP * error is too small to overcome friction, so the robot sits parked short. The integral term adds up the leftover error every millisecond. As time passes, the accumulator grows until it breaks through friction and hits target.

Fix it: Your Own File movements.py 📦

# movements.py -- your own library of robot moves
from pybricks.hubs import PrimeHub
from pybricks.pupdevices import Motor
from pybricks.parameters import Port, Direction
from pybricks.tools import wait

hub = PrimeHub()
left = Motor(Port.F, Direction.COUNTERCLOCKWISE)   # yours
right = Motor(Port.B)                              # yours

KP = 4                                # tuned steering constants
WHEEL_MM = 88                         # measured wheel diameter
DEG_PER_MM = 360 / (3.14 * WHEEL_MM)  # wheel conversion factor
  • Constants at the top: ports, tuning numbers, and wheel sizes
  • Functions below: the moves you call in your missions
  • Main program stays clean: from movements import drive_straight, turn

Walk through creating movements.py alongside the main mission script. Keeping constants at the top makes tuning easy and central. All functions inside the library share these settings.

Verb #2: drive_straight (With Finish Line)

def drive_straight(distance_mm, speed=400):
    """Drive distance_mm while holding gyro heading."""
    heading = hub.imu.heading()                    # lock current heading
    finish = left.angle() + distance_mm * DEG_PER_MM
    while left.angle() < finish:                   # encoder finish line
        error = hub.imu.heading() - heading        # gyro correction
        left.run(speed - KP * error)
        right.run(speed + KP * error)
        wait(5)
    left.stop(); right.stop()
  • The wheel counters work out the finish line
  • The gyro P-loop holds the heading straight
  • One function replaces raw motor commands everywhere

Combine motor encoders with the gyro. Motor encoders determine forward distance; the gyro detects and counters yaw drift. Notice that speed=400 in the function header is a default parameter.

Knobs with defaults 🎛️

Explain default arguments and keyword overrides. When a parameter has an = in the definition, callers can omit it to use the default value, or specify it explicitly to adjust that parameter for a specific maneuver. Required arguments without defaults must always be provided.

Two homes for a name 🗺️

# Top of movements.py (GLOBAL)
hub = PrimeHub()
KP = 4

def drive_straight(distance_mm, speed=400):
    heading = hub.imu.heading()              # LOCAL: created during call
    error = hub.imu.heading() - heading      # LOCAL: deleted when call ends

Local variables

  • Created inside a function
  • Gone the moment the function returns
  • print(error) outside → NameError

Global constants

  • Defined at the top of the file
  • Visible across all functions
  • Update once to tune the entire robot

Contrast scope: variables defined inside a function exist only during that specific function call, preventing accidental variable collisions between different maneuvers. Variables defined at module top level remain available everywhere.

Break it: the tune that didn’t stick 🔥

def make_it_sharper():
    KP = 12          # trying to tune the whole library...

make_it_sharper()
drive_straight(300)  # ...still unchanged! 😤

Why it failed

  • Assigning inside def creates a local variable
  • The global KP at the top was never touched

The rule

  • Read globals from any function
  • Change tuning values only at the top of movements.py

Assigning a variable inside a function creates a local variable in Python unless declared otherwise. Emphasize the clean pattern: never reassign constants inside functions; keep tuning values strictly in the constants block at the top of the file.

The square, in four names

from movements import drive_straight, turn

def drive_square(side_mm):
    for corner in [90, 180, 270, 360]:
        drive_straight(side_mm)
        turn(corner, absolute=True)

drive_square(300)
  • Absolute headings: 90°, 180°, 270°, 360°
  • No stacked drift: each turn aims at the mat on its own
  • 4 lines replace dozens of hand-written ones 🎯
